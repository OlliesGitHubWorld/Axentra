Getting Started

Axentra is a lightweight, all-in-one server management plugin for Minecraft. It replaces multiple plugins with a single jar — moderation, player protection, server health, restarts, maintenance, homes, warps, chat, vanish, and more.

Latest: v1.8.0 — Server Health Update

Adds server health tools (/lag, health score, TPS alerts, cleanup, entity limits), scheduled restarts, maintenance mode, warps and random teleport, tempfreeze and escalating punishments. See the changelog for every change.

Requirements

  • Minecraft server running Spigot or Paper
  • Minecraft 1.21 or higher
  • Java 21 or higher
  • No external dependencies required

Installation

Step 1: Download

Download the latest axentra-x.x.x.jar from one of these sources:

  • GitHub Releases (recommended)
  • SpigotMC
  • Modrinth

Step 2: Install

  1. Place the .jar file in your server's plugins/ folder
  2. Restart your server (or start it for the first time)
  3. Axentra will generate its config files automatically

Step 3: Configure

After the first start, you'll find these files in plugins/Axentra/:

  • config.yml — General plugin settings
  • messages.yml — All plugin messages (fully customizable)
  • punishments.yml — Punishment GUI templates
  • protection.yml — Snapshots, trust, alts, VPN and freeze
  • health.yml — TPS monitoring, lag chunks, alerts, cleanup, entity limits, restarts and maintenance

Edit the files to your liking, then run /axentra reload to apply changes without restarting. Module toggles in enabled-modules require a server restart.

When you update Axentra, new config keys are added to your existing files automatically (with their comments) — your own values are kept.

Building from Source

git clone https://github.com/OlliesGitHubWorld/Axentra.git
cd Axentra
./mvnw clean package

The compiled jar will be in the target/ folder.

Staffmode Tools

When in staffmode, your hotbar contains these tools:

  • Compass — Random teleport to a non-staff player
  • Ice — Right-click a player to freeze/unfreeze them
  • Book — Right-click a player to open their inventory (/invsee)
  • Paper — Right-click a player to view their history
  • Anvil — Right-click a player to open the punishment GUI
  • Ender Eye — Toggle vanish on/off
  • Redstone — Exit staffmode (restores your inventory)

Duration Format

For commands that use durations (tempban, tempmute, tempfreeze, maintenance, etc.), use these formats:

  • 45s — 45 seconds
  • 30m — 30 minutes
  • 12h — 12 hours
  • 7d — 7 days

Warn Auto-Punishments

Configure automatic punishments when players reach warning thresholds:

warn-punishments:
  3:
    action: kick
    reason: "You have accumulated 3 warnings."
  5:
    action: mute
    reason: "You have accumulated 5 warnings."
  7:
    action: tempban
    duration: "1d"
    reason: "You have accumulated 7 warnings."
  10:
    action: ban
    reason: "You have accumulated 10 warnings."

Supported actions: kick, mute, tempban (requires duration), ban and freeze (with a duration it becomes a tempfreeze). Set to {} to disable.

Instead of an exact number you can use a range: "1-10" applies to warns 1 through 10, and "10+" to 10 warns and up. Put range keys in quotes. An exact number always takes priority over a range.

messages.yml

Every message the plugin sends is defined here. All messages support Minecraft color codes (&a, &b, &c, etc.) and placeholders like {player}, {reason}, {staff}, {duration}.

Tip

To find a specific message, search for the key name in the file. Keys are named intuitively, for example ban-message, kick-reason, tpa-request-sent.

punishments.yml

Defines the templates shown in the /punish GUI. Each template has:

FieldRequiredDescription
display-nameYesName shown in GUI (supports & color codes)
actionYeswarn, kick, mute, tempmute, ban, or tempban
reasonYesThe reason shown to the player
durationFor temp*Duration (e.g. 1h, 7d, 30d)
iconYesMinecraft material for the GUI icon
escalationNoA list of steps for repeat offenses. When set, action and duration are ignored

Escalation

With an escalation list, the punishment depends on how many earlier cases the player has with the same reason: the 1st offense uses step 1, the 2nd uses step 2, and so on. After the last step, the last step keeps being used. The GUI shows which step applies (e.g. "Offense #3") before you click.

  spam:
    display-name: "&eSpam"
    action: warn
    reason: "Spamming in chat"
    icon: PAPER
    escalation:
      - "warn"
      - "warn"
      - "tempmute 30m"
      - "tempmute 2h"
      - "tempmute 1d"

Default ladders are included for spam, caps, toxicity, advertising, grief, X-ray, general mutes and lag machines. Remove the escalation block from a template to turn it off.

Server Health

The Server Health update (v1.8.0) helps you find lag before players complain. All settings live in health.yml.

The /lag Overview

/lag shows TPS over 1, 5 and 15 minutes, MSPT (average and peak over the last 100 ticks), memory, uptime, players, entities and loaded chunks per world, and the health score. Clickable buttons open the chunk, entity and history views. On Paper, TPS and MSPT come straight from the server; on Spigot, Axentra measures them itself.

Lag Chunks

/lag chunks gives every loaded chunk a score and lists the 10 heaviest. Each entity counts 1 point, and tile entities that actually tick count extra (hopper 5, spawner 3, furnace 2, …). Chests, signs and other passive blocks count 0, so a chunk full of storage doesn't show up as laggy. Players are never counted. Hover over a chunk to see what's in it, and click [TP] to go there.

Health Score

A single number from 0 to 100 that combines TPS (40%), MSPT (20%), memory (15%), entities per chunk (15%) and open reports plus whether staff are online (10%). 90+ is Excellent, 70+ Good, 50+ Fair and below 50 Poor. The weights and thresholds can be changed in health.yml.

TPS History & Alerts

TPS, MSPT, memory, health and player count are saved every minute. /lag history shows them as 28 time blocks: the color shows the lowest TPS in that block and the stack size the average. When TPS stays below alerts.threshold for alerts.duration-seconds, staff with Axentra.lag.alerts get an alert with the heaviest chunk and its biggest cause, and a recovery message once TPS is back.

Cleanup & Entity Limits

Ground items are cleared every 10 minutes by default, with warnings before each cleanup. Whitelisted materials and named items are never removed. Set cleanup.only-on-alert to clear items only during a lag alert. Entity limits block new spawns once a chunk reaches its limit for a type or group such as ANIMALS.

Scheduled Restarts

Schedule a restart with /restart schedule 10m, or set daily restart times in restarts.daily. Players see a bossbar, warnings in chat, a sound in the last seconds and a title in the last 10 seconds. Commands in pre-commands (like save-all) run first. With auto-restart-on-lag, the server restarts by itself when TPS stays critically low.

Maintenance Mode

/maintenance on 1h30m -c 2m Updating plugins warns players for 2 minutes, then kicks everyone who can't bypass it and locks the server for 1.5 hours. The server list shows a maintenance MOTD with the reason and time left, and players who try to join see when the server is expected back. Maintenance survives restarts and turns off automatically when the duration ends. Ops, players on the maintenance whitelist and players with Axentra.maintenance.bypass can still join.

Warps & RTP

Warps are server-wide teleport points that everyone can use from /warps or /warp <name>. Give a warp a permission with /editwarp <name> permission <perm> to hide it from players without it.

Editing in the GUI

Staff with Axentra.editwarp can manage warps directly in /warps. They see every warp, including its position and permission.

New warps are added at the end of the list. Running /setwarp on an existing warp only moves its location and keeps its icon, permission and position.

Random Teleport

/rtp (or /wild) teleports a player to a random safe spot between min-radius and max-radius from the world's center. Lava, fire, cactus and the void are avoided, and in the Nether the location stays below the bedrock roof. Each world has its own settings in config.yml, and The End is off by default.

Player Protection

The Player Protection update (v1.7.0) helps staff investigate players and undo damage. All settings live in protection.yml.

Inventory Snapshots

Axentra saves a copy of a player's inventory on death, join, quit, world change and /clear. Use /restoreinv <player> to browse snapshots in a GUI and restore one. Old snapshots are removed by max-per-player and max-age-days.

Trust System

Every player has a trust level: NEW → MEMBER → TRUSTED. Players move up automatically based on playtime and a clean record, and are downgraded on punishments. NEW players can be restricted (no links, caps limit, slowmode, no /msg to untrusted players, blocked commands). Staff can override with /trust set.

Alts & VPN

Axentra tracks IP addresses to find accounts that share an IP. /alts <player> shows them with a risk score based on banned alts, VPN usage, trust level and cases. With a free proxycheck.io API key, VPN/proxy connections can be detected on join and either reported to staff or kicked. IP addresses are only visible to staff with Axentra.alts.ip.

Freeze

Frozen players can only move within a small radius (1 block by default), cannot interact, get a reminder every few seconds and can only use allowed commands. Ender pearls and chorus fruit are blocked. The freeze is stored in the database, so logging out or a restart doesn't remove it. When a frozen player logs out, staff can be alerted or the player can be banned automatically.

Use /tempfreeze <player> <duration> for a freeze that ends by itself, even if the player is offline. Frozen players get a [Frozen] tag above their head, in the tab list and in chat, snowflake particles that everyone can see, and an action bar with the time left. Each of these can be changed or turned off in protection.yml.

Timeline & Join Alerts

/timeline <player> shows a player's history: joins, quits, cases, deaths, name changes and IP changes. When a player joins, staff see alts, VPN status, trust level and open cases in one alert.

Punishment GUI

The punishment GUI (/punish <player>) lets staff apply punishments with one click using pre-configured templates.

How It Works

  1. Run /punish <player> to open the GUI
  2. Click a punishment template to apply it
  3. The player is punished and a case is created automatically
  4. Cases get a unique ID and are stored in the SQLite database
  5. View cases with /case <id> or /history <player>

Case System

Every punishment (from GUI or command) creates a case with:

  • Unique ID — Auto-incremented case number
  • Player — The punished player
  • Staff — Who applied the punishment
  • Type — ban, tempban, mute, tempmute, kick, or warn
  • Reason — The punishment reason
  • Timestamp — When it was applied
  • Chat log — Last 20 messages from the player

History GUI

The history GUI (/history <player>) shows all cases for a player in a paginated, color-coded inventory. Click a case to view details. Cases are color-coded by type (red = ban, orange = mute, yellow = warn, etc.).

Staff Notes

Staff notes (/note add <player> <text>) are separate from cases. When a player with notes joins, all staff with Axentra.note permission receive a notification showing the number of notes. View notes with /notes <player>.

Audit Log

Every staff action is logged and viewable with /auditlog <staff> [page]. This includes all moderation actions (ban, mute, warn, kick, etc.) with timestamps.

FAQ

Does Axentra support Paper?

Yes. Axentra works on both Spigot and Paper (and any Paper fork like Purpur).

What Minecraft versions are supported?

Axentra supports Minecraft 1.21 and higher.

Are there any dependencies?

No. Axentra is fully standalone with zero external dependencies. SQLite is bundled inside the jar.

How do I update?

Replace the old jar with the new one and restart your server. Your config files and database are preserved. Use /axentra upgrade to check for new versions in-game.

Can I disable features I don't need?

Yes. Axentra has 30 modules in the enabled-modules section of config.yml — from TPA and homes to vanish, freeze, lag tools and warps. Disabled modules are fully unregistered. See Module Toggles. This requires a server restart.

Can I use Axentra with another chat plugin?

Yes. Set enabled-modules.chat-management to false so Axentra doesn't listen to chat events. Mutes and mute-blocked-commands keep working.

Where is data stored?

All data (bans, mutes, warns, cases, notes, nicknames, audit log, snapshots, homes, warps, TPS history, …) is stored in a local SQLite database at plugins/Axentra/data.db.

What are data.db-wal and data.db-shm?

Since v1.8.0 the database runs in WAL mode, which prevents "database is locked" errors. These two files belong to the database. This is normal — don't delete them while the server is running.

/restart restarts the server immediately

Spigot and Paper have their own /restart. Before v1.8.0 it took priority over Axentra's command — update to the latest version. Spigot's built-in restart is still available as /spigot:restart.

The [Frozen] tag doesn't show above a player's head

The nametag uses the main scoreboard. Plugins that manage nametags themselves, such as TAB, can override it. The tag in the tab list and in chat still works.

Staff can see players' IP addresses

IPs are only shown to players with Axentra.alts.ip. If a group has Axentra.*, explicitly set Axentra.alts.ip to false for staff that shouldn't see them.

How do I reset a config file?

Delete the file and restart the server. Axentra will regenerate the defaults automatically.

I found a bug. Where do I report it?

Open an issue on GitHub Issues or reach out on Discord.
